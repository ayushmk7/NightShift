# Nightshift jac training dataset

Generated by `scripts/dataset.jac` (see its module docstring for the exact extraction logic),
wired into `lib/ship.sh`, `lib/tier2.sh`, and `lib/promote.sh` so it grows automatically every
night. Rebuild from scratch anytime with `bin/nightshift.sh dataset-backfill` — it walks every
bare-named `logs/<date>/` directory (suffixed dirs like `logs/<date>.demo-foo/` are sandbox/test
runs from harness development and are skipped on purpose; they contain synthetic,
non-representative bloat, not real jac code).

Append-only, one file per signal type — join by `date`/`branch`/`file`/`fingerprint`/`session_id`
at training time rather than mutating historical rows.

The harness deliberately does NOT auto-commit these files: the uncommitted diff in `git status`
is the human-review surface for what last night appended. Review, then commit.

## Two schema generations

Rows written before 2026-08-02 carry the v1 shape; every field added since is additive, so old
rows simply lack the newer keys. Read them with `.field // null`, not `.field`. The v1/v2 split
per file is listed under each heading.

Two fields are legacy across all files:

- **`package`** is vestigial. v1 rotated one package per night (`jac`, `jac-byllm`, `jac-scale`);
  v2 audits the whole repo in concurrent shards, so every v2 row pins `package: "repo"` and the
  real axis is `phase` + `name` (the shard) instead.
- **`dry_run`** distinguishes a rehearsal from a live night. It was added because rehearsal nights
  used to be discarded entirely, which threw away real audits and real refactors over one false
  field — the fork URL. A dry-run row is genuine training data with `url: null`; it is not a
  synthetic row.

## `sessions.jsonl`

One row per LLM session — the primitive that makes cost and waste queryable. This is what answers
*"which task type wastes the most money"* and *"are we getting better"* without re-reading logs.

```
{date, package, dry_run, phase, kind, name, task, complexity, theme_slug, attempt, model,
 session_id, total_cost_usd, num_turns, duration_ms, is_error, terminal_reason,
 max_turns_configured, outcome, scope_failed, findings_out, wasted, skipped_reasons}
```

- `phase` — `cycle` (the sharded whole-repo audit) or `reactive` (the merged-PR pass).
- `kind` — `audit`, `audit-repair`, or `apply`.
- `name` — the audit shard (`byllm`, `cli`, `compiler-passes`, ...) or the reactive lens.
- `outcome` — from `parse_result status`: `completed`, or `unfinished:<why>` where `<why>` is
  `max_turns`, `no-envelope` (0-byte file, a timebox kill), `no-result` (the session finished but
  left no `.result`), or `unknown` (an error envelope naming no reason). A session that died is
  never recorded as one that found nothing; that conflation is the defect this file exists to make
  visible.
- `wasted` — true when the session spent money and produced no usable output. Not derived from
  `is_error` alone: a session can complete cleanly, cost $4, and ship nothing.

## `audit_findings.jsonl`

One row per raw finding an audit surfaced, whether or not it ever shipped. `score` is computed for
every row with the same formula the selector packs by (`nslib.score_of`); `fingerprint` is always
populated — `sha1(file + rule)`, stable across nights.

```
v1: {date, package, file, rule, summary, snippet, confidence, risk, score, est_loc_saved,
     fingerprint, status}
v2: ... + {phase, task, complexity, theme_hint, carry}
```

- `status` — `applied`, `not_selected`, or a terminal selector drop reason: `ledger-drafted`,
  `ledger-shipped`, `ledger-rejected`, `over-theme-budget`, `over-night-budget`, `no-clock-left`,
  `blocked-by-protected-test`.
- `task` — which of the four lenses found it (`dead-code`, `maintenance`, `coverage`,
  `abstraction`). The most waste-relevant field in the file, and absent from every v1 row.
- `carry` — true when the finding was banked by an earlier night's audit and re-packed by this
  one, rather than freshly discovered. Carried findings cost nothing to find.

## `refactors.jsonl`

One row **per file** in a branch — the core (bloated-jac → clean-jac) pair data. `before`/`after`
are full file contents pulled via `git show` at the branch's merge-base and tip (not the agent's
self-reported line counts, which were confirmed inaccurate on a real run). `branch` is stored bare
(`nightshift/...`), never `origin/`-prefixed, regardless of which path recorded it.

```
v1: {date, package, branch, file, before, after, diff, finding, agent_summary, risk,
     loc_added, loc_removed, verify, url, suspected_bugs, skipped}
v2: ... + {shipped, dry_run, theme_slug, task, complexity, session_id, total_cost_usd,
           num_turns, model, attempt}
```

- `shipped: false` rows are **declines** — apply sessions that correctly refused, with the real
  reason in `skipped[]` ("deleting X would break Y"). These are high-value negative examples and
  used to be deleted every night.
- `finding` is the originating finding object. v1 rows from the retired tier-1 (deterministic
  autofix, no LLM judgment) carry `null`; tier-1 was retired 2026-07-30 and writes nothing new.
- The cost fields join to `sessions.jsonl` on `session_id` — a refactor's price is not inferable
  from its diff.

## `nights.jsonl`

One row per night whose audit ran **and parsed**, including zero-finding nights — real negative
signal ("here's real jac code, nothing worth flagging" is as informative as a finding). A failed
or unparseable audit records nothing: it says the harness broke, not that the code was clean.
At most one row per `date` — same-day re-runs don't append duplicates.

```
v1: {date, package, findings_count, themes_selected, cost_usd, turns}
v2: ... + {dry_run, phases, findings_carryover, findings_fresh, themes_deferred, declines,
           sessions, session_rows, cost_source}
```

- `themes_selected` is a count of **themes**. In v1 it was mislabelled and carried a *finding*
  count; do not compare the two generations on this field.
- `themes_deferred` is the carry queue — findings the audit paid for that the night had no clock
  or budget to apply. A large gap between `findings_count` and `themes_selected` is the signal
  that audit money is being spent and not converted.
- `cost_usd` / `turns` cover the whole night, every phase, audits plus applies plus repairs.
- `cost_source` — `spend.txt` on a live night (the session ledger, retry-complete and
  overwrite-proof) or `envelopes` when a backfill had to reconstruct the bill from
  `meta-*.json`. The glob undercounts: repair sessions charge the ledger but write no meta file.
- `session_rows` should equal `sessions`. A mismatch means a session ran that this file cannot
  account for.

## `human_reviews.jsonl`

The highest-quality supervision signal: a human ran `nightshift.sh promote` (accepted, opened a
real upstream PR) or `discard` (rejected, reason recorded) on a branch. Join to `refactors.jsonl`
by `branch`. The file does not exist until `promote`/`discard` is actually used.

```
{branch, accepted, reason}
```
